LinkedIn Import — 3 Approaches

How should we fetch and parse the LinkedIn profile data?

A

✨ Direct Fetch + Gemini AI (Recommended)

Your API route fetches the public LinkedIn URL using realistic browser headers, strips the HTML down to text, then sends it to Gemini to extract structured CV data (name, title, summary, experience, education, skills). Uses your existing Gemini integration — no new API keys or costs.

Pros

  • Zero extra cost
  • Reuses existing Gemini setup
  • Works for most public profiles
  • AI handles varied profile structures gracefully

Cons

  • LinkedIn may block some server-side fetches
  • Quality varies if LinkedIn returns login wall
B

💰 Proxycurl API (Paid LinkedIn Scraper)

Use Proxycurl — a third-party API purpose-built for LinkedIn data extraction. Returns clean, structured JSON: name, headline, experience array, education array, skills list. Extremely reliable, no HTML parsing needed.

Pros

  • Most reliable, never blocked
  • Structured JSON — no AI parsing needed
  • LinkedIn-compliant scraping

Cons

  • ~$0.01–$0.02 per profile lookup
  • New API key + billing to manage
  • External dependency
C

🔄 Hybrid — Fetch + AI + Graceful Fallback

Try the direct fetch approach (Option A). If LinkedIn returns a login wall or blocks the request, detect it and show a friendly error with guidance ("Try making your profile public, or try again later"). No paid API, but honest about limitations.

Pros

  • No extra cost
  • Transparent about failures
  • Same as A when it works

Cons

  • May fail for private/semi-private profiles
  • Less predictable success rate

💡 My recommendation: Option A/C — Direct Fetch + Gemini with graceful error handling. It costs nothing extra, leverages your existing Gemini API, and works for most public profiles. If LinkedIn blocks the request, we surface a helpful error. You can always upgrade to Proxycurl later if reliability becomes an issue.
